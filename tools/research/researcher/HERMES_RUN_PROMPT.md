# Prompt to give Hermes: Researcher pilot extraction

Work in `/Users/pushp/Documents/Projects/mobilesurvey`. Read `AGENTS.md`, `docs/researcher-plan.md`, and `tools/research/researcher/README.md` first. Your task is to run a **small, reviewable pilot** of the local Researcher extraction queue for CIUS and CCHS publications. Do not publish to a hosted database or change the Hub's construction page.

1. Check that dependencies are installed and the local OpenAI-compatible model server at `http://127.0.0.1:1234/v1` reports the intended model. Use one inference worker and `LOCAL_LLM_MODEL=qwen3.8-27b` unless the operator specifies another installed local model. Never send article text, credentials, or survey metadata to a cloud model. Keep provider API keys out of `VITE_*` variables.
2. Build `tools/research/researcher/out/pilot-sources.jsonl` from a bounded set of public works. Start with a few CIUS and CCHS works that have a title, stable DOI or URL, and a permitted methods/data passage. Check each source's access and reuse terms. Record source membership accurately (for example `CRDCN`, `Crossref`, `publisher`); a CRDCN Data Used label is a discovery hint only. Include a precise `passageLocation` and only plausible `surveyCandidates`. Use the input shape in the README. Do not invent a passage or exact cycle, and do not store full PDFs in the queue. Put restricted abstracts in local input only with `abstractRights:"restricted"`; they will not be exported.
3. Run `pnpm --filter @mobilesurvey/researcher researcher seed tools/research/researcher/out/pilot-sources.jsonl`, then `... researcher status`. Confirm the number of jobs reflects bounded chunks, and inspect source deduplication.
4. Run `LOCAL_LLM_URL=http://127.0.0.1:1234/v1 LOCAL_LLM_MODEL=qwen3.8-27b pnpm --filter @mobilesurvey/researcher researcher run 25`. Repeat bounded batches only after inspecting status and model memory. The CLI automatically leases, retries, and records failures. Do not run multiple workers until measured safe.
5. Run `... researcher review 50`. Check each candidate against the cited source and full context. Approve only claims with an exact supporting quote, correct canonical program, correct use-versus-mention role, and cycle precision supported by the work's own text. Reject unsupported candidates. A program-only claim is valid when no exact cycle is stated. Treat variable mentions as unresolved unless a literal released variable code is present. Review the theme separately as a paper-level theme. Record reviewer decisions with `approve CLAIM_ID` or `reject CLAIM_ID`; claims with automatic evidence issues cannot be approved until source/extraction is corrected and re-seeded.
6. Export with `pnpm --filter @mobilesurvey/researcher researcher export tools/research/researcher/out/reviewed.jsonl`. Inspect the file for only approved works with an approved `analyzed` claim. Do not import it into D1, Supabase, or a public site yet.
7. Report counts: input works and source overlaps, pending/completed/failed jobs, approved/rejected/pending claims by kind, exact-cycle versus program-only analyzed claims, missing abstracts and rights states, model failures/retries, and review issues. List source URLs for reviewed works. Explicitly identify any missing evidence and limitations. Do not describe this pilot as a census of Statistics Canada data use.

Run package tests and typecheck if dependencies are available. If a source cannot be accessed or rights are unclear, leave it unresolved and continue with other permitted sources; never fill a gap by guessing.
